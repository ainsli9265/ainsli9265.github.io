This live coding engine allows you to specify a melody by entering a space-separated list of notes (A-G#) and rests (_) with stackable length indicators. The octave is set to a default of 4, but can be changed with oct commands. An "oct3", "oct4", or "oct5" changes the octave of all the notes following this indicator. A "-" after a note or rest indicates cutting its length in half (eighth note). A "+" after a note or rest indicates doubling its length (half note). A "." after a note or rest indicates increasing the length by 0.5 (dotted note). Press the button to evaluate your code.

example:
G. C F+ A# D- A D#
oct3 G- A- A#. C- D-- D#- F- G- G- A-- A#- C-- D- D#-- F- G-
oct5 a# c d d# f oct4 a a# g

For this project I implemented a simple, command-based live coding engine in the browser using WebAudioAPI. It allows the user to type short musical commands into a text box, where each line represents an independent track of notes. The input language supports many different notes over multiple octaves, and allows for octave changes in the middle of tracks as well as rhythmic modifiers that lengthen/shorten notes.

When the user presses the start button, the program parses the text input into structured note data containing pitch and length information. This data is stored in liveCodeState, which is used by the audio engine and the visualizer. Each line of code entered by the user is assigned its own oscillator and gain node, allowing multiple lines of notes to play simultaneously. Repeatedly starting and stopping oscillators was causing timing differences or audio clicks. Instead of creating and destroying oscillators for every note, the program keeps oscillators running continuously and uses gain nodes to control when notes are heard. I also decided to go with a triangle waveform because it sounded the best when multiple notes play together and allows the user to hear note changes very clearly. The audio output also passes through a dynamics compressor before reaching the speakers, which helps control sudden peaks in volume when multiple notes overlap.

The program also uses audioCtx.currentTime to schedule notes slightly ahead of playback time. The scheduler calculates how long each loop lasts, tracks the start of the next loop, and keeps rescheduling upcoming notes.

The visualizer is rendered using the HTML canvas API. Every note stored in liveCodeState is drawn as a colored block on a scrolling timeline, with vertical position representing pitch and horizontal width representing duration. Each track is assigned a different color so users can visually distinguish them. The canvas scrolls relative to the audio playback position, and a stationary playhead shows where in the loop the system is. I really liked the pianoroll function in strudel, and wanted to implement it in my own language. This way users can both hear and see the structure of the music.
